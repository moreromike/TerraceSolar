# Savings estimator data

`assets/data/solar-model.json` is generated by `build_model.py`. It holds, for every combination of
area, mounting angle, direction, kit size, shade, daytime-use pattern and battery size, the kWh of
solar the home actually uses in each SDG&E TOU-DR1 period (summer/winter x on/off/super off-peak).
Dollar values are applied in the browser from `SITE_CONFIG.calculator.rates`, so a rate change only
needs the config updated, not this data.

## Sources
- Weather: California Energy Commission CZ2010 typical-year files (Title 24), from NREL's
  openstudio-standards repo (`data/weather/`):
  `SAN-DIEGO-LINDBERGH_722900_CZ2010.epw` (Climate Zone 7) and `RIVERSIDE_722869_CZ2010.epw` (Climate Zone 10).
- Production: pvlib, NREL PVWatts method (Perez transposition, SAPM open-rack cell temperature,
  -0.37%/C, 14% system losses, 96% inverter efficiency, DC/AC 1.0).
- Rates: SDG&E "6-1-26 Schedule TOU-DR1 Total Rates Table" and "6-1-26 Schedule TOU-DR1-CARE_MB Total Rates Table".

## Rebuild
    pip install pvlib
    python3 build_model.py <folder with the two .epw files> out.json
then compact it into `assets/data/solar-model.json` (see the commit that added this folder).

## Assumptions to confirm
- Load patterns (low / medium / high daytime use) are illustrative, not measured.
- Shade derates: some = 20%, a lot = 45%.
- Battery: 90% usable, ~90% round trip, charges only from solar the home can't use, discharges 4 pm to midnight
  up to the kit's inverter capacity. Confirm against CraftStrom's battery documentation.
- Mango Power S AC capacity assumed equal to its 1,200 W panel rating.
